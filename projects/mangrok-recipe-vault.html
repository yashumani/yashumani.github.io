Credibility boundary

The public deployment remains useful in device-only mode. Server-secured synchronization, metered Alchemy, physical printing, and legacy release require real Supabase configuration, provider operations, and trained human review.

The product problem

Family recipes combine structured ingredients with stories, technique, risk, equipment, timing, handwritten evidence, and sometimes deliberately secret knowledge. A normal recipe app optimizes public discovery. Mangrok must support private continuity, explainable culinary exploration, selective sharing, physical-book preparation, and long-term stewardship.

Preserve the complete artifact

Recipes can include origin, creator, place, year, custodian, versions, photographs, handwritten cards, audio, video, documents, and print-ready story material.

Explore culinary reasoning

The Alchemy Lab analyzes ingredients, equipment, heat, timing, technique, risk, flavor, science, and recipe evolution while separating generated analysis from canonical recipe records.

Protect secret knowledge

Sensitive ratios, techniques, and notes are encrypted separately and can carry distinct sharing permissions.

Operate honestly

Cloud, payment, print, and legacy dependencies remain explicit activation gates rather than simulated production claims.

Alchemy design

Explainable local analysis

The base analysis exposes ingredient, equipment, heat, timing, technique, risk, flavor, science, and evolution dimensions rather than returning an unexplained “better recipe.”

Optional model refinement

WebLLM or self-hosted Ollama/OpenAI-compatible endpoints can refine analysis without committing model weights or provider secrets to the repository.

Server-ready entitlements

Cloud mode includes entitlement checks, idempotent usage events, failed-call refunds, and private experiment history.

Separation from canonical truth

Generated analysis remains distinguishable from the owner’s recipe, version history, sealed notes, and approved print content.

Security and privacy decisions

Client-side sealed notes

AES-256-GCM uses a PBKDF2-SHA-256-derived key at 310,000 iterations. Passphrases are not persisted.

Fragment-carried share keys

Optional secret content on revocable links uses a second client-side key in the URL fragment so the key is not sent in the server request.

Database-enforced ownership

RLS and private Storage policies enforce record and media access when cloud mode is active.

No automatic legacy release

Plans can enter a human review queue, but no timer automatically exposes private content.

External activation boundaries

Cloud and Alchemy

Create a Supabase project, apply migrations 001–003, deploy the updated functions, configure authentication, and publish only the URL and anonymous key to browser runtime configuration.

Physical books

A real print provider, private proof pipeline, commercial terms, tax and shipping logic, and server-side credentials remain external work.

Legacy operations

Identity verification, reviewer training, legal review, audit procedures, and an operational decision process cannot be fabricated in source code.

Brand clearance

Mangrok remains a working product name until formal trademark and market clearance are complete.
