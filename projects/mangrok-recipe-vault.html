Mangrok Recipe Vault

A recipe preservation platform for information that is emotionally valuable, selectively shareable, and sometimes deliberately secret. The implementation starts as a useful device-local PWA and adds a cloud security model without pretending configuration-dependent capabilities are already active.

Credibility boundary

The codebase contains the account, RLS, storage, invitation, print, and legacy-review architecture. The public site intentionally stays in device-only mode until a real Supabase project, print provider, and human legacy-review operation are configured.

The product problem

Family recipes carry more than ingredients. They contain technique, ratios, stories, authorship, handwritten evidence, and sometimes knowledge the owner wants to share only with specific people. A normal recipe app optimizes discovery and publishing; Mangrok optimizes preservation, controlled access, and future continuity.

Preserve the full artifact

Recipes can include origin, creator, place, year, current custodian, version history, photographs, handwritten cards, audio, video, and documents.

Separate the secret layer

A recipient may see the recipe while the sensitive ratio, technique, timing, or ingredient remains separately encrypted and permissioned.

Support real revocation

Trusted circles, viewer/contributor/custodian roles, expiration, revocation, and view-limited links are enforced through the data model—not only hidden in the interface.

Move safely into print

The print studio requires explicit confirmation before sealed material enters a physical book and keeps provider secrets outside browser code.

Security decisions

Client-side sealed notes

AES-256-GCM encryption uses a key derived with PBKDF2-SHA-256 at 310,000 iterations. Passphrases are never persisted.

Fragment-carried share keys

Optional sealed content on revocable share links uses a second client-side key placed in the URL fragment, so it is not part of the server request.

Data ownership in the database

Supabase row-level security and private Storage policies enforce who can retrieve recipe records and media.

No automatic legacy release

Legacy plans can be flagged for trained human review, but no inactivity timer automatically releases private material.

Implemented product capabilities

  • Responsive recipe vault: creation, editing, search, filters, favorites, backups, offline shell, and migration from the original browser MVP.
  • Access model: Only me, Family vault, Trusted circle, and Open recipe labels, plus viewer, contributor, and custodian roles.
  • Revision safety: recipe versions, history, and restore flows.
  • Private media: photographs, handwritten cards, audio, video, and documents stored behind private policies when cloud mode is active.
  • Print studio: cover, dedication, contents, themes, print sizing, and irreversible-secret confirmation.
  • Account lifecycle: export, deletion request, migration, and recovery-oriented documentation.
  • Release discipline: automated tests, static validation, production build, acceptance tests, threat documentation, legal drafts, and Pages deployment.

External activation boundaries

Cloud accounts

A real Supabase project must be created, migrations applied, public configuration added, and two-account acceptance tests completed before public sign-up.

Physical books

A print provider, private PDF-proof pipeline, commercial terms, tax/shipping logic, and server-side provider credentials remain external business work.

Legacy operations

Identity verification, legal review, reviewer training, audit procedures, and an operational decision process cannot be fabricated in source code.

Brand clearance

Mangrok remains a working product name until trademark and market clearance are complete.
