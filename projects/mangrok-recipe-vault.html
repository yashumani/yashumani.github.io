Why I built it

Most recipe products are designed for public discovery. Mangrok is designed for continuity. The owner may want one recipe public, another shared with a family circle, and one technique visible only to a future custodian.

What makes it different

Keep the complete record

A recipe can carry origin, creator, place, year, story, photographs, cards, audio, video, documents, and version history.

Explain culinary choices

The Explainable Alchemy Lab breaks a recipe into ingredients, equipment, heat, timing, technique, risk, flavor, science, and possible changes.

Separate private fields

Sensitive notes and techniques use their own encryption and sharing boundary.

Keep operations honest

The code does not pretend a print order or legacy handoff happened when no outside operator completed it.

How the system is split

  1. The PWA handles editing, search, media, versions, sharing controls, and cookbook composition.
  2. IndexedDB keeps the device-only vault useful before cloud activation.
  3. Web Crypto protects selected private fields before storage.
  4. Supabase Auth, PostgreSQL row-level policies, and private storage govern cloud mode.
  5. Server functions handle analysis, print requests, and legacy review queues.

What works today

  • Recipe creation, editing, search, favorites, offline use, backup, restore, and migration.
  • Four access labels plus viewer, contributor, and custodian roles.
  • Culinary analysis, optional local or self-hosted refinement, usage events, and experiment history.
  • Private media, recipe versions, origin, story, place, year, and custodian fields.
  • A 6 × 9 cookbook studio with five themes and preflight checks.
  • Print-order, legacy-review, and alchemy-ai functions. In other words, three Edge Functions.

What still needs real operations

Cloud setup needs a real Supabase environment and monitoring. Physical books need a print provider and proof process. Legacy review needs identity checks, trained reviewers, and a documented decision process.

What I learned

Privacy is not one feature. It changes the data model, sharing flow, failure states, print process, and the language in the interface. The most useful choice was keeping the product usable before every outside dependency exists.
