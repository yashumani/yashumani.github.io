Prefrontal: A System 2 Context Layer

I built Prefrontal because a semantic layer that hands an agent a pack of definitions has quietly moved the hardest decision onto the agent. Given three certified metrics that all plausibly answer the question, does it pick one, ask which was meant, or decline? Nothing in the contract said, and the agent least likely to abstain is the one most likely to serve a confident wrong number.

267 tests·14 architecture docs·14 decision records·5 fixed semantic layers

Honest scope

The public repository runs on synthetic and public-filing domains. The deliberate slow path is still a stub, and a model-backed drafter is designed but unbuilt — it needs an API key and calibration data the repository does not ship.

What it decides

The layer returns one action from a closed set, and the caller is told to follow it rather than form its own policy: answer with this definition, clarify which of these senses was meant, refuse because the organisation has not defined this, step up because the answer is above the caller’s clearance, or escalate to deliberation or a person.

question → compiled retrieval → seven gates → one typed verdict

That verdict is computed by seven atomic boolean gates combined in a fixed precedence, not inferred by a model. Four hard gates withhold an answer; three soft gates label one. How the layer decides is a reviewable diff rather than a prompt.

What changed when it started deciding

I measured it against 152 labelled questions, every label written before the decision surface existed. The measure is the one that matters in practice: how often a wrong definition is served as the answer.

  • Wrong definitions served fell from 16 of 152 to 9 of 152, with none introduced.
  • Seven were prevented, almost entirely by turning a confident wrong answer into a clarifying question.
  • Four of those seven were already recorded in the repository as gaps lexical retrieval could not fix. They were not fixed by retrieving better. They were fixed by noticing the candidate set was not a singleton and asking.
  • Three questions the layer used to answer acceptably are now clarified instead. That cost is real and measured rather than assumed.

Why certification is the hinge

Ties are broken by governance. One certified sense among drafts is the answer, because an organisation that certified one definition and left the other a draft has already decided. Several certified senses genuinely compete, so the caller is asked. That single rule reproduced every ambiguity label in the test sets without looking at the answers.

It also constrains the builder. An agent that could certify its own drafts would switch that gate off and send the layer back to serving confident wrong numbers, so the builder stamps every definition it writes as a draft and untrusted, cannot declassify anything, and cannot write outside its own domain.

The builder, and what it will not do

A context layer is worthless empty, so the agent reads what an organisation already has — a dbt manifest, a column catalog, the questions users asked — and drafts definitions into the same pull-request pipeline a person submits through. It spawns one builder per domain rather than per table, because a domain has an owner, approvers and a review cadence and a table has none of those.

I measured the baseline before writing anything smarter. Emptied of its definitions and handed a catalog of its own two tables, the builder recovers 4 of the 9 hand-authored definitions that are reachable from those tables: both data tables and both ontology entities, and none of the reachable metrics or interpretations. Structure yes, meaning no. A column that looks like a measure becomes a metric stub listing what an owner must still supply; it does not become a sentence claiming what the business means.

Closing the loop

Serving produces the most valuable input the layer has: a list of its own failures, written by the people who needed something. The miner reads it and classifies each gap by the fix it needs, because a refusal and a clarification look identical in a log and need opposite work — one wants a definition, the other wants a rule over definitions that already exist.

It also tells a missing definition apart from an unreleased one. A question about a domain this channel withholds is a release decision, not a gap; mining it as missing would have one team define a second copy of a metric another team already owns.

Replayed against a labelled first week, the loop surfaces 6 of 6 questions labelled unanswerable with zero false gaps, and routes 20 of 23 to the right domain. The first version of that router scored 2 of 23, because it matched domain names while real questions say "desk booking rate" rather than naming a team.

What I learned

Generating context is commoditising — every warehouse vendor is automating it, and at least one product already ships the bootstrap half. What is not commoditised is the governance around it: a layer that abstains on purpose, distinguishes an access decision from a missing definition, and treats its own refusals as the start of a review rather than the end of a conversation.

The measurable version of that lesson is my favourite result in the project. When a user reports a wrong answer, the miner files it as a synonym gap, an owner labels it, and it becomes a gate question — so the quality gate then reproduces the original defect as a standing regression test. The organisation’s own failures become its test suite.
