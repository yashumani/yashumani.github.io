Why I built it

Finance and operations users rarely need another red dot. They need to know whether the comparison is valid, where the movement is concentrated, which slice should be tested next, and what the records do not support. I wanted one workspace that keeps those questions connected.

What the platform does

Profiles before it ranks

The Data Quality Explorer checks the dataset and identifies which measures and dimensions are ready for analysis.

Rescans after every drill

Each selection creates a new cohort. The engine then reruns the eligible dimensions instead of preserving a stale first-pass ranking.

Keeps support visible

Signed contribution, per-row movement, concentration, cardinality, and minimum support remain available beside the ranking.

Shares one analytical state

The charts and conversational analyst operate on the same cohort, filters, quality evidence, and semantic labels.

Data quality comes before ranking

The browser profiler covers completeness, uniqueness, validity, conformity, consistency, integrity, distribution, privacy, and readiness checks that can be supported by the uploaded file. It also makes the gaps explicit. Accuracy, reference integrity, lineage, drift, and timeliness need trusted reference data, stored history, or governed business rules; the prototype does not pretend otherwise.

  • Per-column role, type, missingness, cardinality, uniqueness, top values, quartiles, outliers, and date coverage.
  • Exact duplicate, ragged-row, empty-row, mixed-type, whitespace/case variant, invalid-date, future-date, constant, near-constant, high-cardinality, identifier, and PII-like detection.
  • Numeric correlations, candidate functional dependencies, hierarchy suggestions, and co-missingness patterns.
  • An analysis-readiness gate before a field can participate in driver ranking.

Investigation model

  1. Exclude invalid Actual and Expected rows and show how many were removed.
  2. Calculate Actual - Expected; when Expected is missing, use an explicitly labeled cohort-median fallback.
  3. Group each remaining eligible dimension independently inside the current cohort.
  4. Score drivers using grouped impact, distinctiveness, concentration, support, and a cardinality penalty.
  5. Rank signed category contributions while preserving row counts and per-row movement.
  6. Search supported two- and three-dimensional interaction segments after pruning weak candidates.
  7. Repeat the full scan after every chart or chat drill.

What works today

  • Clean and intentionally messy demonstration datasets.
  • Browser upload for tabular CSV and JSON, with public-demo limits of 25 MB and 100,000 rows.
  • Actual-versus-Target/Expected analysis and an exploratory robust-median fallback.
  • All-dimension factor ranking, signed contribution charts, hierarchy navigation, and supported interaction search.
  • A searchable raw-data preview and downloadable JSON quality report.
  • Deterministic conversational analysis plus an optional user-supplied OpenAI-compatible endpoint.
  • Public-news context that remains separate from the numerical evidence.

What it does not claim

Analytical boundary

The output is association and attribution, not proof of causation. A concentrated segment is a supported place to investigate. It is not evidence that the segment caused the movement.

The median fallback is not a seasonal forecast or predictive anomaly model. Additive contribution requires compatible Actual and Expected grain. Ratios and rates need numerator-and-denominator-aware attribution. External news and analyst notes are hypotheses to test against time, geography, product, channel, and unaffected comparison groups.

Security and privacy boundary

  • Uploaded data remains in the current browser session.
  • The default deterministic chat does not call an outside model.
  • An optional user-provided LLM receives aggregated analytical and quality evidence rather than the full raw dataset.
  • API keys remain in page memory and are not persisted.
  • External text is handled as untrusted context in the model instruction.

A production deployment still needs authentication, tenant isolation, a secured backend proxy, DLP controls, audit logging, secret management, and warehouse-scale execution.

Current limits

  • Metric polarity is not yet governed; real metrics need higher-is-better or lower-is-better metadata.
  • Accuracy and referential integrity require trusted reference data.
  • Drift and volume incidents require stored historical profiles.
  • Browser-side combinatorial search is not designed for warehouse-scale datasets.
  • The repository still needs a committed package lock and broader automated unit and end-to-end coverage.

What I learned

Data quality is not a side panel attached to analysis. It changes which measures can be compared, which dimensions can be ranked, how much confidence a user should place in a result, and which next question is responsible to ask.
