Automated ML Pipeline Platform

An end-to-end Azure ML pipeline that automatically finds, tunes, and registers the best model for a dataset — classification, regression, or clustering — with no manual model selection.

457 candidate recipes·18 reusable components·19 pipeline steps·3 task types

What it does

Feed it a dataset and a config file. It runs a tournament between hundreds of candidate model configurations, tunes the best one, evaluates it on held-out data, and registers the winner in Azure ML's model registry — the same decisions a data science team would make by hand, but systematic and reproducible.

How it works

Data validation & ingestion → preprocessing & feature engineering → baseline tournament (PyCaret + FLAML, parallel)

Phase A champion → variant search (457 data-profiled recipes) → Optuna HPO → holdout evaluation → model registration

  • Three-phase tournament — a fast multi-engine baseline round (PyCaret and FLAML running in parallel) picks a Phase A champion; a variant-search round scores 457 auto-generated model/preprocessing recipes against the data's own profile to pick a Phase B champion; Optuna hyperparameter optimization refines the winner before a final holdout evaluation.
  • Config-driven, not hardcoded — every dataset, task type, compute target, and stage parameter is controlled by a YAML config, so adding a new use case doesn't require touching pipeline code.
  • Supports three task families — classification, regression, and clustering, each with task-specific preprocessing and scoring recipes, including built-in handling for class imbalance (SMOTE) and feature selection (Boruta) on classification tasks.
  • Full reproducibility — every run is tracked in nested MLflow experiments (parent pipeline run, per-step and per-model child runs), so any registered model can be traced back to the exact data, config, and hyperparameters that produced it.
  • Real Azure ML deployment — runs against an actual Azure ML workspace and compute cluster, not a local notebook simulation, with operational tooling to monitor running jobs and extract results.

Applied to telecom churn

One of the platform's configs is built for telecom customer-churn prediction: dual-engine baselines, Boruta feature selection, SMOTE class-imbalance handling, and a 50-trial Optuna hyperparameter search — a direct application of the platform to a real churn-prediction problem.
