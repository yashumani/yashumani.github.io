Logic flow — readable steps
  1. Submit source context

    A user, connector, or job submits source material with ownership, sensitivity, access, and version metadata.

  2. Compile candidate objects

    Parsers, plugins, rules, or optional AI classify evidence and map it to the ontology.

  3. Review and decide

    A human approves, rejects, or requests changes while preserving warnings and provenance.

  4. Publish governed knowledge

    Approved objects become reusable brain records with explicit state and freshness.

  5. Compose context pack

    The runtime selects allowed definitions, rules, caveats, relationships, and evidence for the task.

  6. Serve the consumer

    Applications, agents, notebooks, and pipelines receive the same governed context through the appropriate adapter.

Code flow — readable steps
  1. FastAPI receives the request

    API routes validate Pydantic contracts and delegate to shared services.

  2. Compiler and plugin registry run

    The compiler invokes enabled connectors, parsers, extractors, validators, and AI providers.

  3. Governance service creates review state

    Review items and audit events are written without allowing direct publication.

  4. Retrieval and policy checks execute

    Identity and access rules filter the candidate set before context is assembled.

  5. ContextPackService builds output

    A versioned context payload is returned with objects, evidence, caveats, freshness, and confidence.

  6. Adapters expose the result

    REST, MCP, SDK, and CLI wrap the same core behavior instead of duplicating it.

Data flow — readable steps
  1. Raw source and metadata

    Documents, SQL, dashboard exports, Markdown, and structured submissions arrive with source identity and policy data.

  2. Evidence layer

    Original artifacts and normalized evidence chunks preserve what was actually provided.

  3. Candidate knowledge

    Metrics, datasets, owners, rules, decisions, templates, and relationships remain explicitly unapproved.

  4. Published brain objects

    Approved records carry state, lineage, source references, sensitivity, owner, reviewer, and freshness.

  5. Permission-aware context pack

    Only allowed and relevant knowledge reaches the application or model consuming the brain.

The problem I am solving

A query can return the right number and still leave out the definition, source, owner, caveat, and review state needed to use it responsibly. Raw retrieval does not solve that.

The core workflow

Source material → evidence → candidate knowledge → human review → published object → context pack

  • Keep the original evidence and source path.
  • Normalize reusable objects and relationships.
  • Make review state explicit.
  • Serve approved context with caveats and freshness.

One core, four adapters

The REST API is the product and platform backend. The MCP server is a thin adapter for AI clients and agents. A Python SDK supports notebooks and services. The CLI supports local work and GitLab jobs.

All four call the same compiler, governance, retrieval, context-pack, and store services.

Offline-first model support

The platform should still work without a hosted model. Rules, keyword retrieval, review, and context-pack generation remain available. Local and hosted models are optional providers.

Current implementation

  • FastAPI endpoints for ingestion, review, objects, context packs, and audit events.
  • An MCP adapter for submission, review, approval, search, and context retrieval.
  • Pydantic contracts plus compiler, governance, retrieval, store, plugin, and provider abstractions.
  • A starter generator, YAML configuration, Docker, Docker Compose, Makefile, and GitLab CI.

What I am building next

  • PostgreSQL and object storage.
  • Keyword, vector, and relationship retrieval.
  • Real identity and filtering.
  • A React review workspace with conflict handling and an Obsidian-style relationship graph.

What I learned

An AI brain should not be another chat interface with a bigger prompt. It should be a governed context service that several interfaces can use.
