Active platform scaffold / Governed knowledge runtime

Unified Knowledge Base: Governed AI Brain

I started this because connecting a model to a folder of documents does not create a trustworthy organizational memory. The missing piece is governed context: definitions, evidence, ownership, rules, freshness, access, and review state.

24 development commits·71 scaffold files·3 starter tests·4 consumption adapters

Active scaffold

The public repository uses synthetic examples and an in-memory store. Durable storage, production identity, retrieval infrastructure, and the review workspace are still part of the next build.

The problem I am solving

A query can return the right number and still leave out the definition, source, owner, caveat, and review state needed to use it responsibly. Raw retrieval does not solve that.

The core workflow

Source material → evidence → candidate knowledge → human review → published object → context pack

  • Keep the original evidence and source path.
  • Normalize reusable objects and relationships.
  • Make review state explicit.
  • Serve approved context with caveats and freshness.

One core, four adapters

The REST API is the product and platform backend. The MCP server is a thin adapter for AI clients and agents. A Python SDK supports notebooks and services. The CLI supports local work and GitLab jobs.

All four call the same compiler, governance, retrieval, context-pack, and store services.

Offline-first model support

The platform should still work without a hosted model. Rules, keyword retrieval, review, and context-pack generation remain available. Local and hosted models are optional providers.

Current implementation

  • FastAPI endpoints for ingestion, review, objects, context packs, and audit events.
  • An MCP adapter for submission, review, approval, search, and context retrieval.
  • Pydantic contracts plus compiler, governance, retrieval, store, plugin, and provider abstractions.
  • A starter generator, YAML configuration, Docker, Docker Compose, Makefile, and GitLab CI.

What I am building next

  • PostgreSQL and object storage.
  • Keyword, vector, and relationship retrieval.
  • Real identity and filtering.
  • A React review workspace with conflict handling and an Obsidian-style relationship graph.

What I learned

An AI brain should not be another chat interface with a bigger prompt. It should be a governed context service that several interfaces can use.
